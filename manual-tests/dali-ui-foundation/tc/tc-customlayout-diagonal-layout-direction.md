# CustomLayout: Diagonal LayoutDirection Toggle

`ArrangeCallback`이 항상 `LEFT_TO_RIGHT` 기준으로 계산해도, 해석된 방향이 `RIGHT_TO_LEFT`이면 프레임워크가 직접 자식을 수평 미러링하는지 확인한다.

## 화면 구성

- 배경은 흰색이고, 루트는 `MeasureCallback` / `ArrangeCallback`이 등록된 `Layout`이다
- `MeasureCallback`은 폭으로 사용 가능한 전체 폭을, 높이로 자식 높이의 합(350)을 반환한다
- 자식 3개가 추가 순서대로 대각선 배치된다
  - 자식 1: 50x50, 빨강 `Vector4(0.9, 0.2, 0.2, 1.0)`
  - 자식 2: 100x100, 초록 `Vector4(0.2, 0.7, 0.2, 1.0)`
  - 자식 3: 200x200, 파랑 `Vector4(0.2, 0.3, 0.9, 1.0)`
- 좌상단 (0, 0)에 200x50 반투명 검정 `Vector4(0.0, 0.0, 0.0, 0.5)` 토글 버튼이 있고, 흰색 `Change LayoutDirection` 라벨이 가운데 정렬되어 있다
- 토글 버튼은 `LayoutMode::STANDALONE`이며 자신의 `LayoutDirection`은 `LEFT_TO_RIGHT`로 고정되어 있다
- 두 콜백은 모두 `LayoutMode::STANDALONE` 자식을 건너뛰므로, 토글 버튼은 측정과 배치 계산에 포함되지 않는다

## 테스트 1: 초기 LTR 배치

1. 목록에서 이 TC를 선택해 진입한다
2. **기대 결과**: 빨강 50x50, 초록 100x100, 파랑 200x200이 좌상단에서 시작하는 대각선으로 배치된다
3. **기대 결과**: 각 박스의 좌상단 모서리가 이전 박스의 우하단 모서리에 닿는다
4. **기대 결과**: 토글 버튼은 좌상단 (0, 0)에 200x50 크기로 놓인다. 버튼이 반투명(알파 0.5)이므로
   같은 자리에 있는 빨강 50x50 박스 위에 겹쳐 비쳐 보인다

## 테스트 2: RIGHT_TO_LEFT 전환

1. `Change LayoutDirection` 버튼을 탭한다
2. **기대 결과**: 루트의 `LayoutDirection`이 `RIGHT_TO_LEFT`가 되어 세 박스가 루트 폭을 기준으로 좌우 반전된다
3. **기대 결과**: 빨강은 우상단에서 시작하고, 초록과 파랑이 왼쪽 아래로 이어지는 대각선이 된다
4. **기대 결과**: 각 박스의 세로 위치와 크기는 테스트 1과 동일하다
5. **기대 결과**: 토글 버튼은 `LayoutMode::STANDALONE`이므로 미러링되지 않고 좌상단에 그대로 남는다

## 테스트 3: LEFT_TO_RIGHT 복귀

1. `Change LayoutDirection` 버튼을 다시 탭한다
2. **기대 결과**: 배치가 테스트 1의 LTR 대각선으로 정확히 복귀한다
3. **기대 결과**: 여러 번 반복해도 두 상태만 번갈아 나타난다

## 통과 기준

- 콜백은 항상 `LEFT_TO_RIGHT` 프레임으로 계산하고, 미러링은 프레임워크가 콜백 반환 이후에 수행해야 한다
- `RIGHT_TO_LEFT`에서 세 박스의 x 좌표만 루트 폭 기준으로 반전되고 y 좌표와 크기는 변하지 않아야 한다
- `LayoutMode::STANDALONE` 토글 버튼은 방향과 무관하게 항상 좌상단 (0, 0)에 200x50으로 유지되어야 한다
- 토글 버튼은 측정과 배치 대상에서 제외되므로 다른 자식들의 위치에 영향을 주지 않아야 한다
- 목록으로 나갔다가 다시 진입하면 항상 `LEFT_TO_RIGHT` 상태로 초기화되어야 한다
