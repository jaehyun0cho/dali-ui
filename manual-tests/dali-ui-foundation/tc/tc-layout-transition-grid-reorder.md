# LayoutTransition: Grid Reorder (Long-press Drag)

`GridLayout`의 셀을 길게 눌러 끌어 순서를 바꿀 때, 빈 슬롯(프록시)이 손가락을 따라가고
모든 셀의 Row / Column 재할당이 `LayoutTransition`의 CHANGE 슬롯으로 애니메이션되는지 확인한다.

## 화면 구성

- 루트는 흰색 `AbsoluteLayout`이며 콘텐츠 영역 전체를 채운다(이 루트가 곧 배경이다)
- 그 위 (80, 80) 위치에 400x600 크기의 반투명 회색 패널(`(0.5, 0.5, 0.5, 0.5)`)이 놓이며
  모서리 반경 40px, padding 20px, 자식 간 spacing 20px이다
- 패널의 첫 행: 오른쪽 정렬된 타일 2개(각 50x50, 라벨 없음). 왼쪽이 notification 자리(`#FFC107` 호박색),
  오른쪽이 edit 자리(`#9E9E9E` 회색)이며 간격 20px이다
- 패널의 둘째 행: 왼쪽에 `wifi` 버튼, 오른쪽에 `bluetooth` 버튼. 각 버튼은 100x100 타일 +
  오른쪽에 흰색 이름 라벨(폰트 16)이 붙은 가로 구성이다
- 패널의 셋째 행: 세로 `ScrollView` 안의 3열 `GridLayout`. 셀 크기는 120x150이고 셀은 12개
  (`brightness`, `color`, `energy`, `game`, `multi view`, `output display`, `picture`,
  `settings`, `share`, `sound`, `support`, `timer`)이다
- 각 셀은 100x100 타일 위에 흰색 이름 라벨(폰트 14)이 아래로 붙은 세로 구성이며 spacing 4px이다
- **아이콘 자리는 동일 크기의 단색 타일로 대체됨**: 원본 샘플은 SVG 아이콘을 읽어 오지만
  매뉴얼 테스트 리소스 디렉터리에는 해당 SVG가 없으므로, 크기·라벨·셀 형상은 그대로 두고
  아이콘만 모서리가 둥근(반경 = 크기의 25%) 단색 타일로 바꿨다. 12개 셀은 서로 다른 색을
  써서 개별 식별이 가능하다
- 그리드의 CHANGE 타이밍은 0.4초 `EASE_IN_OUT_SINE`이다

> 상단 헤더(60px)만큼 세로 공간이 줄어들므로 최하단 요소는 창 크기에 따라 일부만 보일 수 있다.

## 테스트 1: 길게 눌러 집어 올리기

1. 그리드 셀 하나를 0.5초 이상 길게 누른다
2. **기대 결과**: 누른 셀이 떠올라 손가락을 따라올 준비가 되고, 원래 자리에는 같은 크기의
   빈 슬롯이 남는다. 이때 다른 셀은 움직이지 않는다
3. 손을 그대로 뗀다
4. **기대 결과**: 셀이 원래 자리로 되돌아가고 순서는 바뀌지 않는다

## 테스트 2: 드래그로 순서 재할당

1. 셀을 길게 눌러 집은 뒤 다른 셀 위로 끈다
2. **기대 결과**: 떠 있는 셀의 중심이 이웃 셀 절반(가로 60px, 세로 75px)을 넘어설 때마다
   빈 슬롯이 그 자리로 옮겨 가고, 모든 셀의 Row / Column이 재할당되어 0.4초 CHANGE로 재배치된다
3. 가로·세로 양방향으로 여러 칸 이동해 본다
4. **기대 결과**: 3열 구조가 유지된 채 행/열을 넘나드는 이동이 모두 반영된다

## 테스트 3: 놓기

1. 원하는 위치에서 손을 뗀다
2. **기대 결과**: 떠 있던 셀이 놓은 화면 위치에서 시작해 빈 슬롯 자리로 미끄러져 들어가며,
   순간이동 없이 이어진다
3. **기대 결과**: 최종 순서가 드래그 중 보였던 빈 슬롯 위치와 일치한다

## 테스트 4: 가장자리 자동 스크롤

1. 셀을 집은 뒤 `ScrollView` 뷰포트의 위쪽 또는 아래쪽 60px 이내로 끌고 간다
2. **기대 결과**: 손가락을 멈춰도 그리드가 그 방향으로 자동 스크롤되고,
   가장자리에 가까울수록 속도가 빨라진다(최대 한 틱당 12px)
3. 자동 스크롤 중 손가락을 그대로 둔다
4. **기대 결과**: 화면 밖에 있던 셀 위치까지 순서를 옮길 수 있다

## 테스트 5: 길게 누르기 전 이동 취소

1. 셀을 누른 뒤 0.5초가 지나기 전에 20px 이상 손가락을 움직인다
2. **기대 결과**: 드래그가 시작되지 않는다(스크롤 의도로 판단하여 길게 누르기가 취소됨)
3. 셀 사이의 빈 여백을 이용해 위아래로 끌어 본다
4. **기대 결과**: `ScrollView`가 정상적으로 스크롤된다

## 테스트 6: 드래그 도중 뒤로 가기

1. 셀을 집어 끌고 있는 상태로(손을 떼지 않고) `< Back`을 눌러 목록으로 나간다
2. 다시 이 TC로 들어온다
3. **기대 결과**: 12개 셀이 `brightness` → `timer`의 초기 순서로 되돌아가 있다
4. **기대 결과**: 화면 어디에도 떠 있던 셀이 남아 있지 않고 빈 슬롯도 남지 않는다
5. 목록 화면으로 돌아가 다른 TC를 열어 본다
6. **기대 결과**: 이전 TC의 셀이 겹쳐 보이지 않는다

## 통과 기준

- 0.5초 이상 길게 눌렀을 때만 드래그가 시작되어야 한다
- 길게 누르기 전 20px 이상 움직이면 드래그가 시작되지 않아야 한다
- 드래그 중 빈 슬롯이 손가락을 따라 이동하고, 셀 재배치가 0.4초 `EASE_IN_OUT_SINE` CHANGE로
  애니메이션되어야 한다
- 셀을 집는 순간과 놓는 순간에 셀이 순간이동하거나 다른 셀이 튀지 않아야 한다
- 뷰포트 위/아래 60px 이내에서 자동 스크롤이 동작하고, 그동안에도 순서 재계산이 계속되어야 한다
- 드래그 중 뒤로 가기 후 재진입해도 화면에 떠 있는 잔여 뷰가 없고 초기 순서로 복귀해야 한다
